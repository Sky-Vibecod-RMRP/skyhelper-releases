# SKY HELPER (этап 11)

Считает онлайн на дежурстве и обращения по горячей клавише. Окно с прогрессом к
недельной норме и стриком, значок в трее с живыми цифрами, экран настроек.
Отчёты: Excel, PNG и Google Таблица. Плюс локальный сайт с данными в реальном времени —
открывается и на ПК, и с телефона в той же Wi-Fi сети.

## Быстрый старт (EXE)

1. Один раз собери EXE: двойной клик по `build_exe.bat` (нужен Python 3.10+ на Windows).
2. **Установщик для админов** (собирается после exe; нужен Inno Setup 6 —
   `winget install -e --id JRSoftware.InnoSetup`):

       "%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" installer\SKYHELPER.iss

   На выходе `dist\SKYHELPER_Setup.exe`: ставит программу в
   `%LOCALAPPDATA%\Programs\SKY HELPER` **без запроса UAC**, создаёт ярлыки,
   по желанию автозапуск и «запуск от администратора», удаляется через
   «Установка программ». Настройки, статистика и активация переживают
   переустановку. Проверено дымовым прогоном (см. `Отчёты\Инсталлятор_2026-10-01.txt`).
3. Без установки: `dist\SKYHELPER.exe` — копируй куда хочешь,
   запускай двойным кликом.
4. Сразу в трей, без окна: `SKYHELPER.exe --minimized`.
   Для автозапуска положи ярлык с этим ключом в `shell:startup` (Win+R)
   либо поставь галочку в установщике.
5. Если игра запущена от имени администратора, запускай трекер тоже от администратора,
   иначе горячие клавиши не сработают поверх игры (в установщике есть галочка).
6. **Инструкция для того, кому выдаёшь exe:** `Инструкция_для_админов.txt` —
   активация ключом, клавиши, скриншоты, сайт, частые ошибки. Её можно
   просто переслать вместе с файлом программы (или с установщиком).

## Лицензия: активация ключом

EXE работает только с ключом — ключ выдаётся **под конкретный компьютер**
и на ограниченный срок.

**Пользователю:**

1. При первом запуске появится окно активации с кодом этого ПК вида
   `RM-XXXX-XXXX-XXXX-XXXX`. Нажми «Копировать код» и отправь его администратору.
2. Администратор пришлёт ключ — длинную строку. Вставь её в поле (кнопка
   «Вставить» или Ctrl+V) и нажми «Активировать».
3. Дальше программа запускается как обычно. Срок и «свой ли это ПК»
   проверяются при каждом запуске; при наличии интернета сверяется ещё
   и список отозванных ключей.
4. Ключ закончился или переустановил Windows (код ПК изменился) —
   отправь администратору новый код и получи новый ключ.
5. В настройках есть вкладка **«Лицензия»**: текущий статус, срок,
   кнопка «Копировать код» и поле для продления ключа.

**Администратору проекта (выдача ключей):**

```bat
:: один раз: создать пару ключей
python tools/gen_key.py init
:: приватный ключ ляжет в ~\.rmrp_signing_key.pem — нужен бэкап!

:: выдать ключ под код ПК пользователя на 30 дней
python tools/gen_key.py key --hwid "RM-XXXX-XXXX-XXXX-XXXX" --days 30 --who "Ник"

:: ключ под собственный компьютер
python tools/gen_key.py key --this-pc --days 365

:: отозвать ключ (убрать доступ немедленно)
python tools/gen_key.py revoke --add ABCD-EFGH
```

Команда `revoke` печатает готовый подписанный файл — его содержимое
публикуется как публичная gist-запись на GitHub, а адрес вписывается в
настройках (вкладка «Лицензия» → «Список отзывов (адрес)»). У пользователя
отозванный ключ перестаёт работать при следующем запуске программы
с интернетом; без сети программа работает по последнему скачанному списку.

## Автообновления: правишь код — у админов появляется версия

Админам больше не надо присылать файлы руками: программа сверяет свою
версию с манифестом, предлагает обновление в течение дня, а через сутки
после выпуска **старая версия перестаёт запускаться** (только обновиться
или выйти). Работает только в собранном `exe`; в исходниках просрочка
лишь напоминает — не мешает разработке.

### Нужно один раз: репозиторий-витрина

1. GitHub → **New repository** (публичный), например `skyhelper-releases`.
   Исходники туда НЕ кладём: в корне только `README.md` (одна строка)
   и дальше — `manifest.json` с каждым релизом.
2. В папке витрины: `git init`, добавить README, создать репозиторий,
   push.
3. Вписать адрес в код (одной командой):

   ```
   python tools\make_release.py 1.1.0 --repo OWNER/REPO --notes "..." ^
       --skip-tests --skip-exe --skip-installer
   ```

   (это обновит `UPDATE_REPO` в `app/update_check.py`; можно и вручную)

### Каждый релиз

```
python tools\make_release.py 1.1.0 --notes "Что нового: ..."
```

Скрипт: поднимет `VERSION`, прогонит тесты, соберёт exe и установщик,
посчитает SHA-256, подпишет манифест твоим приватным ключом
(`~\.rmrp_signing_key.pem`, тот же, что у лицензий) и напечатает
чек-лист выкладки:

* `release\manifest.json` → в папку витрины, `git add/commit/push`;
* `dist\SKYHELPER_Setup.exe` → GitHub → Releases → тег `v1.1.0`.

### Что видит админ

* проверка при запуске, не чаще раза в 6 часов;
* вышла версия — окно «Доступна версия X (у вас Y): обновитесь в
  течение дня», кнопки «Обновить сейчас» / «Напомнить позже»;
* прошли сутки — окно без откладывания: обновиться или выйти;
* обновление: скачивание установщика (~76 МБ) с прогрессом → сверка
  SHA-256 и подписи → молча ставится → программа перезапускается.
  Настройки, активация и статистика сохраняются;
* нет интернета — проверка молча пропускается; но если программа уже
  получила манифест с просрочкой, без интернета (и обновления) её
  не запустить. Откат системных часов отключённую версию не вернёт:
  сроки считаются по `max(время, отметка в state)`.

### Безопасность

* манифест подписан Ed25519 теми же ключами, что и лицензии: без
  верной подписи обновление не принимается;
* SHA-256 сверяется **до** запуска установщика;
* клиент ходит на `raw.githubusercontent.com` и `releases/download` —
  без API и его лимитов; в витрине нет исходников;
* приватный ключ остаётся у тебя — см. бэкап в разделе «Лицензия».

## Управление

- **F10** = начать/закончить дежурство (или кнопка в окне, или пункт в трее).
  Онлайн и обращения считаются только на дежурстве и при запущенной игре.
  Когда игра закрывается, дежурство выключается само.
- **F9** = +1 обращение, **Ctrl+F9** = −1.
- Раз в 2 часа плашка с темпом за сегодня.
- Закрытие окна сворачивает в трей. Полный выход: трей → правая кнопка → «Выход».
- Всё, что раньше правилось вручную в config.json, теперь есть в окне настроек
  (кнопка «Настройки» в окне и в трее). Настройки применяются сразу, без перезапуска.
- **Хелпер** (кнопка «Хелпер» в окне, пункт «Хелпер…» в трее): цветное меню
  разделов инструкций слева, справа текст; отдельный раздел — «Правила RMRP»
  с поиском по 28 правилам форума.

## Сайт с живыми цифрами

Включи его в настройках: вкладка «Сайт» → «Включить локальный сайт» → «Сохранить».
Кнопка «Открыть сайт» есть в окне и в трее.

- Адрес: `http://127.0.0.1/` — только этот ПК.
- С телефоном: включи «Разрешить доступ с телефона» (программа слушает `0.0.0.0`)
  и открой `http://<IP-ПК>/` — IP посмотри в свойствах сети или в `ipconfig`.
  Компьютер и телефон должны быть в одной Wi-Fi сети.
- **Код доступа**: задай его в той же вкладке, если разрешил доступ по сети —
  без кода открыть страницу сможет любой в твоей сети. Код хранится хэшем
  (pbkdf2), в логи не попадает, 5 неудач подряд = минута ожидания.
- В шапке три вкладки: **Дашборд** (сам обновляется каждые 3 секунды: сегодня
  с часами, обращениями и полосой к плану, неделя, стрик, статус дежурства/игры
  и столбики за 7 дней), **Хелпер** (инструкции карточками — тот же текст,
  что и в окне программы) и **Правила RMRP** — 28 правил по трём категориям
  с поиском и подсветкой совпадений, ссылки открываются на forum.rmrp.ru.
- Порт (по умолчанию 80 — чтобы ссылка была без «:8080») и код меняются там же.
  Порт занят — программа напишет об этом
  в окно и в журнал, а не упадёт.

## Настройки

Семь вкладок: «Основное» (дежурство, клавиши, недельные нормы, процесс игры),
«Отчёты» (папка, периодичность, архив PNG), «Сайт» (вкл/выкл, сеть, порт, код),
«Google» (ID таблицы и JSON-ключ), «Вид и звуки» (тема оформления и сигналы),
«Скриншоты» (папка недели и 8 категорий) и «Лицензия» (статус ключа, код ПК,
адрес списка отзывов).

## Стрик и уведомления

- Стрик в окне и на сайте = сколько дней подряд закрыта дневная норма.
  День закрыт, если набраны **и** часы, **и** обращения по дневному плану
  (недельная норма / 7, например 10 ч и 86 обращений).
- Сегодняшний день пока не засчитан — он показывается как «в процессе» и стрик не ломает.
- Темы интерфейса: тёмная (как в отчётах), полночь, светлая.
- Звуки: без звуков, системные, мягкие тоны — включаются/выключаются в настройках,
  там же кнопка «Проверить звук». Сигналы: дежурство вкл/выкл, обращение ±1,
  удачный и неудачный экспорт.

## Куда всё сохраняется

Папка `Документы\SKY HELPER\` (меняется через `output_dir` в config.json):

- `SKYHELPER_stats.xlsx`: три листа.
  - «Неделя»: блоки идут по порядку чтения — прогресс к недельной норме, «Сегодня:
    план на день и факт», сравнение с прошлой неделей, прогноз к концу недели,
    итог за месяц. Сверху подпись, как читать цвета процентов.
  - «По дням»: дни по порядку — от раннего к позднему; дата, день, онлайн (ч:мм),
    часы, обращения, план и выполнение в процентах, строка «ИТОГО», диаграмма.
  - «Динамика»: последние 8 недель таблицей (от текущей недели назад) и
    комбинированной диаграммой (часы столбцами, обращения линией).
- `SKYHELPER_report.png`: дашборд в стиле Grafana — пять карточек KPI («Сегодня»,
  онлайн за неделю, обращения, среднее в день, прогноз), график по дням Пн–Вс
  с подсветкой сегодняшнего дня и линией среднего, сравнение с прошлой неделей,
  итог за месяц.
- `История\SKYHELPER_report_ГГГГ-ММ-ДД.png`: копия отчёта по каждой неделе
  (дата = понедельник). К концу недели в файле лежит итог.
- В трее: «Открыть папку с отчётами».

Обновление раз в 2 часа и через 30 секунд после запуска, плюс пункт трея
«Обновить таблицу сейчас». Занятый в Excel файл не мешает PNG и Google обновиться.

База, настройки и журнал: `%APPDATA%\SKYHELPER\` (`data.db`, `config.json`, `logs\app.log`).
Настройки меняй через окно «Настройки» — оно сразу сохранит config.json (UTF-8)
и перезапустит нужные части. Файл, отредактированный руками, подхватится
только после перезапуска программы.

## Google Таблица (по желанию)

Нужно один раз настроить сервисный аккаунт:

1. Открой console.cloud.google.com, создай проект.
2. «APIs & Services» → «Library»: включи **Google Sheets API** (и Google Drive API).
3. «APIs & Services» → «Credentials» → «Create credentials» → «Service account».
   Открой созданный аккаунт → «Keys» → «Add key» → JSON. Скачается файл.
4. Положи его как `%APPDATA%\SKYHELPER\google_key.json`
   (или укажи другой путь в `gsheet_credentials`).
5. Создай пустую Google Таблицу. Нажми «Настройки доступа» и добавь e-mail сервисного
   аккаунта (`client_email` из JSON, вида `...@...iam.gserviceaccount.com`) с ролью «Редактор».
6. Из адреса таблицы `https://docs.google.com/spreadsheets/d/ВОТ_ЭТО/edit` возьми ID
   и впиши в config.json: `"gsheet_id": "ВОТ_ЭТО"`. Перезапусти программу.

Листы «Неделя» и «По дням» создаются сами и перезаписываются при каждом обновлении.
Если выгрузка не удалась, в окне появится жёлтая строка с причиной, а Excel и PNG всё равно обновятся.
Проще всего без настройки Google API: указать `output_dir` внутри папки Google Диска
для компьютера, тогда xlsx синхронизируется сам (но это будет файл, а не живая таблица).

## Установка и запуск из исходников

```
python -m pip install -r requirements.txt
python -m app.gui_main            # с окном
python -m app.gui_main --minimized
python -m app.main                # консольный режим
python -m pytest                  # тесты (нужен requirements-dev.txt)
```

Имя процесса игры проверь так: `python tools/list_processes.py gta rage`,
и впиши найденное в `game_processes` в config.json (сейчас стоит `GTA5.exe`).
